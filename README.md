# Mini NPU Simulator

## 실행 방법

1. Python 3.8 이상을 설치합니다.
2. `main.py`와 `data.json`을 같은 폴더에 둡니다.
3. 터미널에서 `python main.py`를 실행합니다.
4. `1`은 직접 입력 모드, `2`는 JSON 분석 모드입니다.

## 구현 요약

- MAC은 패턴과 필터의 같은 위치 값을 곱한 뒤 모든 곱을 누적하는 계산입니다.
- `mac_score`는 표준 라이브러리만 사용하고 중첩 반복문으로 직접 계산합니다.
- `data.json`의 키 `cross`/`x`와 expected의 `+`/`x`를 각각 표준 레이블 `Cross`/`X`로 정규화합니다.
- JSON 키 `size_{N}_{idx}`에서 크기 N을 읽어 대응하는 `size_N` 필터를 선택합니다.
- 점수 차이의 절댓값이 `1e-9` 미만이면 동점 `UNDECIDED`로 판정합니다.
- 크기 불일치, 잘못된 숫자, 누락된 스키마는 JSON 케이스 단위 FAIL로 기록합니다.

## 결과 리포트

- 안내문의 `data.json`을 실행해 총 6개 케이스를 확인했습니다.
- 결과는 PASS 3개, FAIL 3개였습니다.
- `size_5_2`, `size_13_1`, `size_25_2`는 판정 레이블과 expected가 같아 PASS였습니다.
- `size_5_1`, `size_13_2`, `size_25_1`은 점수 차이가 epsilon 미만이어서 `UNDECIDED`가 됐고, expected 레이블과 일치하지 않아 FAIL입니다.
- 이 FAIL은 키나 스키마 문제 대신 데이터의 부동소수점 점수와 과제의 동점 정책에서 발생했습니다.
- `0.9`와 `0.8999999999999999`처럼 실수 연산 결과가 아주 조금 달라도 epsilon 기준으로 동점 처리됩니다.
- `UNDECIDED`를 Cross 또는 X로 임의 판정하지 않는 것이 안내문의 판정 정책과 일치합니다.
- 행렬 크기가 N×N이면 각 원소를 한 번씩 처리하므로 MAC 연산 횟수는 N²입니다.
- 따라서 시간 복잡도는 O(N²)이며, 표의 연산 수 9, 25, 169, 625는 각각 N²와 같습니다.
- 성능은 MAC 함수만 1,000회 호출해 측정한 평균이며, 입력·출력과 파일 읽기 시간은 포함하지 않습니다.
- 측정 시간은 컴퓨터와 Python 실행 환경에 따라 달라지므로 절대 성능 비교보다 크기 증가 추세를 해석합니다.
- 3×3 성능 측정은 사용자 입력 모드에서 입력한 패턴과 필터 A로 수행했습니다.

## 성능 측정 결과

아래 값은 사용자가 2026-11-19에 직접 실행해 확인한 결과입니다. 3×3 값은 사용자 입력 모드 실행에서, 나머지 크기는 JSON 분석 모드 실행에서 측정했습니다.

| 크기 | MAC 연산 수 (N²) | 측정 호출 수 | 평균 시간 (ms) |
|---|---:|---:|---:|
| 3×3 | 9 | 1,000 | 0.003639 |
| 5×5 | 25 | 1,000 | 0.004743 |
| 13×13 | 169 | 1,000 | 0.015713 |
| 25×25 | 625 | 1,000 | 0.051998 |

측정값은 실행 환경의 부하에 따라 달라질 수 있습니다. 이번 실행에서는 행렬 크기가 커질수록 연산 수와 평균 시간이 증가했습니다. 모드별로 실행한 측정값이므로 실행 조건 차이가 있을 수 있습니다.
